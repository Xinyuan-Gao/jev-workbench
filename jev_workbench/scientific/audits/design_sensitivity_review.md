# 设计敏感性与路由标注独立复核

复核日期：2026-10-07。复核范围为设计代码、其保存的候选报告、候选数据分组、正式比较配置，以及路由标注交付状态。没有修改源码，没有调用远程 API，没有运行正式模型 test，也没有使用 test 预测来选择样本量。

## 结论

`exact_paired_power()` 的双侧精确 McNemar 功效计算，在其声明的 IID 二元配对假设下计算正确；独立三项分布直接枚举与原实现一致。当前报告应继续称为“测试前、假设条件下的设计敏感性”，不能称为达到 80% 功效的保证，也不能证明两个模型差异必然有统计意义。

实际候选 MASSIVE test 为 558 条、558 个组，每组一条。T2 test 为 674 对问题—片段、200 个问题组；组大小分别为 13 组两条、100 组三条、87 组四条。两份路由表各 1,600 条、所有标注字段仍为空；本轮尚无真人路由 gold。

## 独立计算验证

原代码把不一致记录数 M 的二项概率，与给定 M 时的条件拒绝概率混合求和。M=0 时精确检验不会拒绝原假设，因此代码从 M=1 开始求和正确。零假设的两尾拒绝界线由 p=0.5 的精确二项尾部确定，`cutoff=-1` 对没有可拒绝结果的 M 给出零条件功效；上尾 `sf(M-cutoff-1)` 的边界正确。

交叉实现没有使用 `binom.ppf`、原代码的条件功效表达式或不一致数的混合求和。直接枚举三类计数 `(a,b,c)`：A 对/B 错、A 错/B 对、两者一致，概率分别为 `(q+δ)/2`、`(q-δ)/2`、`1-q`。对每个计数用整数二项系数计算零假设双侧 p 值：

`2 * sum(comb(a+b,j), j=0..min(a,b)) / 2**(a+b)`。

使用精确有理数 α=1/20 或 1/80 决定拒绝域，再直接对拒绝域上的 alternative 三项分布概率求和。此做法独立于原代码的分位数及混合计算路径。

- 小样本覆盖 n=1..15，q=0.1/0.2/0.4/0.6/1，δ=0/0.05/q，α=0.05/0.0125，共 450 次比较，包括零效应、边界效应及 q=1。最大绝对差为 1.7764×10^-15。
- 当前 n=558 的全部八个假设组合也直接枚举；最大绝对差为 2.0784×10^-13，符合浮点计算误差。
- Wilson 最坏半宽以独立等价式 `z/(2*sqrt(n+z*z))` 验证；n=200 与 558 均一致，最大绝对差低于 10^-14。

## 必须保留的统计边界

1. **5 个百分点是事先设定的正确率差异假设。** 它不是模型真实效应的预测，也不是 Macro-F1 的效应假设。q 也是假设；仅知道 n 和 δ 不能唯一确定配对检验的功效。上表已经说明，在不同 q 下，558 条并不总能达到 80%。
2. **四项比较是当前两项正式候选任务各两项。** 配置指定 JEV–Gemini、JEV–由 validation 选出的最佳本地基线；当前 MASSIVE 的本地入选模型为 LR，T2 为 Linear SVC。α=0.05/4=0.0125 是 Holm 第一个、最保守门槛的敏感性情形，并非正式检验时每项都使用同一门槛，也不是实际已经调整的显著性结果。若路由之后转为正式任务，比较数与敏感性说明须在任何正式 test 前重新冻结。
3. **MASSIVE 一条一组只是分组结构证据，不能证明 IID。** 当前每类限额抽样、自然语言相似性和潜在来源依赖仍可能影响模型。JSON 的 `exact_mcnemar_applicable_to_primary=true` 必须理解为结构上没有“一 query 多 passage”的重复单位，且仍以独立配对等条件成立为前提；不能把此布尔值当作已经证明独立同分布。协议中的分层成对 bootstrap 与稀有类别 support 说明应保留。
4. **T2 不能把 674 对片段当成 674 个独立观察。** 同一问题的片段共享问题内容。其 passage 正确率差异应按 query 进行成对重采样/置换；二元 McNemar 功效不是其主要指标的精确功效。200 个问题本身也不能保证 80% 功效。
5. **Kish 193.803754 是组大小权重的集中度。** 它不是测得的组内相关系数，也不是已经确定的有效样本量；不能将其代入 Bernoulli 精确检验后宣称解决了群组依赖。
6. **Wilson 的 4.1344/6.8639 个百分点是 IID Bernoulli 说明。** 特别是用 200 得到的半宽不是 674 passage 正确率的正式置信区间；也不是两个模型差值的区间。正式区间须遵循冻结的抽样和群组单位。
7. **不支持看 test 后再补样或选停。** “未显著”不等于模型相当，也不等于没有真实差异。应同时报告预先定义的差值和区间、任务局限及敏感性。重复远程运行不能当作增加独立任务样本量。

## 路由标注状态与实际交付

对项目内 `data_sources/routing/route_annotation_A.csv` 和 B 表逐项核验：每份均 1,600 个唯一 item_id，两表同 ID 的完整字段一致、行顺序不同；全部 task SHA256 与 input_sha256 一致。`annotation`、`reason`、`uncertain` 的非空值数量分别为 0、0、0。当前指南记录的源 schema SHA256 与 `task_schemas.py` 实际 SHA256 一致。

实际下一步为：

1. 将 A 表和 `GUIDE.md` 交给第一位真人，将 B 表及同版本指南交给另一位真人。CSV 以全列文本导入，避免改动任务文字和哈希。两人独立填写，不能查看对方标签、模型预测或原对话助手回答。
2. 每人只填最后三列：annotation 填 clarify/search/code/writing；reason 记一句判断依据；uncertain 填 yes/no。遇定义歧义保留不确定记录，不让模型代填。
3. 收回两份原始提交，保留标注人匿名编号、完成时间、指南版本，按 item_id 合并；先核验文字哈希、缺失和非法标签，再统计未裁决一致率、四类混淆与 Cohen's kappa。
4. 由指定真人裁决分歧和不确定记录，保留两份原始判断、裁决理由及最终标签。如果定义需要改版，统一重标对应记录。随后才确定路由任务是否纳入正式比较、分区和最低验收要求，并在模型 test 前冻结。

两份空白表不能称为“双人标注已完成”。在真实人工标签与裁决交付前，路由只能保持待验收的候选/探索性任务状态，不能依靠 LLM 代填凑齐本轮正式实验。
